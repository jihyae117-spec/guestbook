# 방명록(Guestbook) 요구사항 정의서

- 작성일: 2026-08-08
- 버전: v1.0
- 대상: 방명록 웹앱 (프론트엔드 + 백엔드 + DB 직접 구축)

## 1. 개요

누구나 이름 또는 별명으로 글을 남길 수 있는 방명록 웹 서비스. 작성 시 비밀번호를 설정하여
본인만 추후 수정/삭제할 수 있도록 하고, 다른 방문자는 각 글에 답글을 남길 수 있다. 답글 또한
동일하게 비밀번호 기반으로 수정/삭제가 가능하다. 스팸/도배 방지 기능과 관리자 권한을 포함한다.

## 2. 용어 정의

| 용어 | 설명 |
|---|---|
| 글(Entry) | 방문자가 남기는 최상위 방명록 게시물 |
| 답글(Reply) | 특정 글에 종속되어 달리는 댓글 |
| 작성자 비밀번호 | 글/답글 작성 시 설정하는 비밀번호. 수정·삭제 시 본인 확인 용도로 사용 |
| 관리자 | 비밀번호 확인 없이 모든 글/답글을 삭제할 수 있는 운영 계정 |

## 3. 사용자 유형

| 유형 | 권한 |
|---|---|
| 방문자(비로그인) | 글 작성, 답글 작성, 본인이 작성한 글/답글의 비밀번호 확인 후 수정·삭제 |
| 관리자 | 별도 로그인 후 모든 글/답글 강제 삭제. 비밀번호 불필요 |

※ 별도의 방문자 회원가입/로그인은 없음 (이름/별명은 매번 자유 입력, 중복 허용).

## 4. 기능 요구사항

### 4.1 글 작성 (FR-1)

- 방문자는 다음 항목을 입력하여 글을 작성할 수 있다.
  - 이름/별명 (필수, 1~20자)
  - 내용 (필수, 1~500자)
  - 비밀번호 (필수, 4자 이상, 수정/삭제 시 사용)
- 비밀번호는 평문으로 저장하지 않고 해시(bcrypt 등)로 저장한다.
- 작성 즉시 목록에 노출된다 (별도 승인 절차 없음).
- 작성 시각(작성일시)이 자동으로 기록된다.

### 4.2 글 목록/상세 조회 (FR-2)

- 방문자는 로그인 없이 모든 글과 답글을 조회할 수 있다.
- 목록은 최신순으로 정렬하며 페이지네이션(또는 무한 스크롤)을 지원한다.
- 비밀번호, 비밀번호 해시 등 민감정보는 목록/상세 응답에 절대 포함하지 않는다.

### 4.3 글 수정 (FR-3)

- 방문자는 글 수정 시 비밀번호 입력을 요구받는다.
- 입력한 비밀번호가 저장된 해시와 일치할 경우에만 수정이 허용된다.
- 수정 가능 항목: 이름/별명, 내용 (비밀번호 자체는 수정 불가 — 필요 시 별도 정책 논의)
- 수정 시 "수정됨" 표시 및 수정일시를 기록한다.
- 비밀번호 불일치 시 명확한 오류 메시지를 반환하고, 무차별 대입 방지를 위해 시도 횟수를 제한한다 (예: 5회 실패 시 일정 시간 잠금).

### 4.4 글 삭제 (FR-4)

- 방문자는 삭제 시 비밀번호 입력을 요구받으며, 일치할 경우에만 삭제된다.
- 삭제 방식은 소프트 삭제(논리 삭제)를 기본으로 하며, 삭제된 글에 달린 답글도 함께 조회 목록에서 제외한다.
- 삭제 전 확인(컨펌) 절차를 거친다.

### 4.5 답글 작성 (FR-5)

- 임의의 방문자는 특정 글에 답글을 남길 수 있다.
- 입력 항목은 글 작성과 동일: 이름/별명, 내용(1~300자 권장), 비밀번호.
- 삭제된(비활성) 글에는 답글을 작성할 수 없다.

### 4.6 답글 수정/삭제 (FR-6)

- 답글도 글과 동일한 방식으로 본인 비밀번호 확인 후 수정/삭제 가능하다 (4.3, 4.4와 동일 정책).
- 원글이 삭제되면 하위 답글은 별도 조작 없이 화면에서 함께 숨김 처리된다.

### 4.7 스팸/도배 방지 (FR-7)

- 글/답글 작성 시 캡차(예: 간단한 수식 캡차 또는 Google reCAPTCHA)를 적용한다.
- 이름 20자, 글 내용 500자(답글 300자) 등 글자 수 제한을 둔다.
- 동일 IP/세션 기준 연속 등록 제한(예: 10초 이내 재등록 차단, 1분당 최대 N회)을 적용한다.
- 서버 측 Rate Limiting을 적용하여 API 남용을 방지한다.
- (선택) 금칙어 필터링을 고려할 수 있다.

### 4.8 관리자 기능 (FR-8)

- 별도의 관리자 로그인(아이디/비밀번호 또는 인증 토큰)이 존재한다.
- 관리자는 비밀번호 확인 없이 모든 글/답글을 삭제할 수 있다.
- 관리자 계정 정보는 일반 방문자와 분리되어 관리되며, 관리자 비밀번호도 해시로 저장한다.
- 관리자는 현재 등록된 모든 글/답글 목록을 엑셀(.xlsx) 파일로 내보낼 수 있다. 글 시트와 답글 시트로 구분하며, 비밀번호(해시 포함)는 어떤 경우에도 내보내기 결과에 포함하지 않는다.
- (선택) 관리자 삭제 이력(누가/언제/무엇을 삭제했는지) 로그를 남기는 것을 권장한다.

## 5. 비기능 요구사항

### 5.1 보안

- 모든 비밀번호(방문자·관리자)는 bcrypt 등 안전한 해시 알고리즘 + salt로 저장한다.
- 비밀번호는 API 응답에 절대 노출되지 않는다.
- 수정/삭제 API는 서버에서 비밀번호 재검증을 반드시 수행한다 (클라이언트 검증만으로 신뢰하지 않음).
- XSS 방지를 위해 사용자 입력(이름, 내용)은 저장/출력 시 이스케이프 처리한다.
- HTTPS 통신을 기본으로 한다.
- 관리자 인증에는 세션 또는 JWT 등 표준 인증 방식을 사용한다.

### 5.2 성능/가용성

- 목록 조회는 페이지당 최대 20~30건 수준으로 페이지네이션한다.
- 일반적인 소규모 트래픽(동시 사용자 수십~수백 명)을 기준으로 설계한다.

### 5.3 데이터 보존

- 삭제된 글/답글은 소프트 삭제로 처리하여 필요 시 복구/감사가 가능하도록 한다 (운영 정책에 따라 일정 기간 후 영구 삭제 고려).

## 6. 데이터 모델 (초안)

### 6.1 entries (글)

| 필드 | 타입 | 설명 |
|---|---|---|
| id | PK | 고유 ID |
| name | varchar(20) | 이름/별명 |
| content | varchar(500) | 내용 |
| password_hash | varchar | 해시된 비밀번호 |
| created_at | datetime | 작성일시 |
| updated_at | datetime | 수정일시 (nullable) |
| is_deleted | boolean | 삭제 여부 (소프트 삭제) |

### 6.2 replies (답글)

| 필드 | 타입 | 설명 |
|---|---|---|
| id | PK | 고유 ID |
| entry_id | FK → entries.id | 원글 참조 |
| name | varchar(20) | 이름/별명 |
| content | varchar(300) | 내용 |
| password_hash | varchar | 해시된 비밀번호 |
| created_at | datetime | 작성일시 |
| updated_at | datetime | 수정일시 (nullable) |
| is_deleted | boolean | 삭제 여부 (소프트 삭제) |

### 6.3 admins (관리자)

| 필드 | 타입 | 설명 |
|---|---|---|
| id | PK | 고유 ID |
| username | varchar | 관리자 아이디 |
| password_hash | varchar | 해시된 비밀번호 |

## 7. 화면 요구사항 (초안)

- **방명록 목록 화면**: 글 목록(이름, 내용 일부, 작성일), 글쓰기 버튼, 페이지네이션
- **글쓰기 폼**: 이름/별명, 내용, 비밀번호 입력, 캡차, 등록 버튼
- **글 상세/답글 영역**: 글 전체 내용 + 하위 답글 목록 + 답글 작성 폼
- **수정/삭제 시**: 비밀번호 입력 모달 → 검증 성공 시 수정 폼 표시 또는 삭제 확인 후 처리
- **관리자 화면**: 관리자 로그인 페이지, 전체 글/답글 목록에서 삭제 버튼 노출

## 8. 향후 고려사항 (Out of Scope for v1)

- 방문자 회원가입/로그인 (SNS 로그인 등)
- 이미지/파일 첨부
- 글 신고 기능
- 이메일 알림 (답글 등록 시 알림)
- 다국어 지원
